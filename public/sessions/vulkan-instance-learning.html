Creating a VkInstance is the first real Vulkan call — it roots the object hierarchy, declares which window-system extensions the app needs, and establishes the connection between your code and the Vulkan driver.

Complete createInstance()
Standard path (Windows / Linux)
void createInstance() { VkApplicationInfo appInfo{}; appInfo.sType = VK_STRUCTURE_TYPE_APPLICATION_INFO; appInfo.pApplicationName = "Hello Triangle"; appInfo.applicationVersion = VK_MAKE_VERSION(1, 0, 0); appInfo.pEngineName = "No Engine"; appInfo.engineVersion = VK_MAKE_VERSION(1, 0, 0); appInfo.apiVersion = VK_API_VERSION_1_0; VkInstanceCreateInfo createInfo{}; createInfo.sType = VK_STRUCTURE_TYPE_INSTANCE_CREATE_INFO; createInfo.pApplicationInfo = &appInfo; uint32_t glfwExtensionCount = 0; const char** glfwExtensions; glfwExtensions = glfwGetRequiredInstanceExtensions(&glfwExtensionCount); createInfo.enabledExtensionCount = glfwExtensionCount; createInfo.ppEnabledExtensionNames = glfwExtensions; createInfo.enabledLayerCount = 0; if (vkCreateInstance(&createInfo, nullptr, &instance) != VK_SUCCESS) { throw std::runtime_error("failed to create instance!"); } }
macOS fix (MoltenVK SDK ≥ 1.3.216)
std::vector<const char*> requiredExtensions; for (uint32_t i = 0; i < glfwExtensionCount; i++) { requiredExtensions.emplace_back(glfwExtensions[i]); } requiredExtensions.emplace_back(VK_KHR_PORTABILITY_ENUMERATION_EXTENSION_NAME); createInfo.flags |= VK_INSTANCE_CREATE_ENUMERATE_PORTABILITY_BIT_KHR; createInfo.enabledExtensionCount = (uint32_t) requiredExtensions.size(); createInfo.ppEnabledExtensionNames = requiredExtensions.data();
Optional: enumerate supported extensions
uint32_t extensionCount = 0; vkEnumerateInstanceExtensionProperties(nullptr, &extensionCount, nullptr); std::vector<VkExtensionProperties> extensions(extensionCount); vkEnumerateInstanceExtensionProperties(nullptr, &extensionCount, extensions.data()); std::cout << "available extensions:\n"; for (const auto& extension : extensions) { std::cout << '\t' << extension.extensionName << '\n'; }
Cleanup
void cleanup() { vkDestroyInstance(instance, nullptr); // must come first glfwDestroyWindow(window); glfwTerminate(); }
Logic Flow

The instance is Vulkan's root object — the first real API object created and the last destroyed. Everything else in the tutorial (physical device selection, logical device, swap chain) hangs off it. That makes instance creation the critical handshake between the application and the Vulkan driver, and the two structs involved — VkApplicationInfo and VkInstanceCreateInfo — each serve a distinct purpose in that handshake.

VkApplicationInfo is optional but meaningful. The driver can inspect the engine name and version and apply known optimizations or compatibility workarounds for well-known engines (Unreal, Unity, etc.). The tutorial fills it with placeholder values; real applications would use their actual names. The struct follows the universal Vulkan struct pattern: an sType field that identifies the struct type to the runtime, a pNext pointer for extension chaining (set to nullptr here via value-initialization), and then the actual data fields.

VkInstanceCreateInfo is where the mandatory work happens. It points to the application info struct and, crucially, lists the global extensions to enable. Vulkan has no built-in knowledge of any window system — it's intentionally portable across Win32, Cocoa, Wayland, and others. The extensions needed to bridge Vulkan to the active window system are provided by GLFW via glfwGetRequiredInstanceExtensions(), which returns a platform-appropriate list. Without those extensions, creating a window surface later will fail. Validation layers are also declared here, but the tutorial defers them to the next chapter — enabledLayerCount is set to zero for now.

The vkCreateInstance call itself establishes the three-argument pattern common to all vkCreateXXX functions: a pointer to the creation info struct, a pointer to a custom VkAllocationCallbacks (nullptr throughout this tutorial), and a pointer to the output handle. The return value is a VkResult; the tutorial inlines it in an if-not-equals-VK_SUCCESS check and throws on failure.

The macOS portability issue reveals an important evolution in the MoltenVK ecosystem. Since SDK 1.3.216, the VK_KHR_portability_subset device extension became mandatory on Apple GPUs, and to enumerate devices that expose it you must set VK_INSTANCE_CREATE_ENUMERATE_PORTABILITY_BIT_KHR on the instance flags and add VK_KHR_PORTABILITY_ENUMERATION_EXTENSION_NAME to the extension list. Omitting either causes VK_ERROR_INCOMPATIBLE_DRIVER — a misleading error code that makes it look like no Vulkan driver is present.

Extension enumeration with vkEnumerateInstanceExtensionProperties introduces a two-call pattern that reappears throughout Vulkan: call once with a nullptr array to get the count, allocate a vector of that size, call again to fill it. This pattern appears again for physical device enumeration, queue family queries, and swap chain details — recognizing it here makes subsequent chapters easier to follow.

Step-by-Step — Creating the Instance
  1. Add VkInstance as a private member and declare createInstance()
    WHYThe instance handle must outlive the createInstance() call so cleanup() can destroy it later. Making it a class member (not a local variable) ties its lifetime to the application object.
  2. Call createInstance() from initVulkan()
    WHYInstance creation is the first step in the Vulkan init sequence; it must precede everything else in initVulkan() because all subsequent vkCreate calls depend on a valid VkInstance.
  3. Fill VkApplicationInfo
    WHYProvides optional app metadata the driver may use for optimizations. Even with placeholder values, setting apiVersion to VK_API_VERSION_1_0 tells the driver the minimum Vulkan version the app targets.
    WATCH OUTAlways set sType to VK_STRUCTURE_TYPE_APPLICATION_INFO — missing or wrong sType produces undefined behaviour.
    • a. appInfo.sType = VK_STRUCTURE_TYPE_APPLICATION_INFO
    • b. appInfo.pApplicationName = "Hello Triangle"
    • c. appInfo.applicationVersion = VK_MAKE_VERSION(1, 0, 0)
    • d. appInfo.pEngineName = "No Engine"
    • e. appInfo.engineVersion = VK_MAKE_VERSION(1, 0, 0)
    • f. appInfo.apiVersion = VK_API_VERSION_1_0
  4. Fill VkInstanceCreateInfo and link to appInfo
    WHYThis is the mandatory struct that drives instance creation. Linking pApplicationInfo = &appInfo passes the optional metadata through.
    WATCH OUTappInfo must remain in scope until vkCreateInstance returns — it's passed by pointer, not by value.
  5. Query GLFW for required extensions and set them on createInfo
    WHYVulkan has no built-in window system support. GLFW's glfwGetRequiredInstanceExtensions() returns the platform-specific extension names that must be enabled for surface creation to succeed later.
    WATCH OUTOn macOS (MoltenVK SDK ≥ 1.3.216): copy the extensions into a vector, append VK_KHR_PORTABILITY_ENUMERATION_EXTENSION_NAME, and set VK_INSTANCE_CREATE_ENUMERATE_PORTABILITY_BIT_KHR on createInfo.flags — or vkCreateInstance returns VK_ERROR_INCOMPATIBLE_DRIVER.
    • a. glfwGetRequiredInstanceExtensions(&glfwExtensionCount)
    • b. createInfo.enabledExtensionCount = glfwExtensionCount
    • c. createInfo.ppEnabledExtensionNames = glfwExtensions
  6. Set enabledLayerCount = 0
    WHYValidation layers are deferred to the next chapter. Setting the count to zero explicitly (value-initialization does this too) avoids reading uninitialized memory.
  7. Call vkCreateInstance and check the result
    WHYReturns VK_SUCCESS on success or an error code on failure. Throwing std::runtime_error on failure follows the tutorial's error propagation pattern — caught in main() and printed.
    WATCH OUTVK_ERROR_EXTENSION_NOT_PRESENT means a requested extension isn't supported. Use vkEnumerateInstanceExtensionProperties beforehand to detect this.
  8. Add vkDestroyInstance(instance, nullptr) as the first call in cleanup()
    WHYAll Vulkan resources created from the instance must be destroyed before the instance itself. Placing this first in cleanup() ensures it is always last in the destruction sequence as more resources are added in later chapters.
    WATCH OUTvkDestroyInstance must come before glfwDestroyWindow — not after. Destroying the window first can cause issues when Vulkan surface objects (added later) still reference the GLFW window handle.
