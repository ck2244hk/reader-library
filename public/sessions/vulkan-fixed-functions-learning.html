Every fixed-function stage that older APIs configured silently by default must now be declared explicitly in Vulkan — baked into an immutable pipeline state object — except for a small set of states you opt into making dynamic so they can be changed at draw time without recreating the pipeline.

Pipeline State Structs at a Glance
VkPipelineVertexInputStateCreateInfo
Describes vertex buffer layout — bindings (stride, per-vertex vs per-instance) and attribute descriptions. Empty when vertex data is hardcoded in the shader.
VkPipelineInputAssemblyStateCreateInfo
Specifies how vertices are assembled into primitives.
topology — TRIANGLE_LIST / STRIP / POINT_LIST…
primitiveRestartEnable — special index breaks strips
VkPipelineViewportStateCreateInfo
Declares viewport and scissor counts; values set at draw time when dynamic.
viewportCount / scissorCount — must always be set
pViewports / pScissors — nullptr when dynamic
VkPipelineRasterizationStateCreateInfo
Configures the rasterizer — the geometry-to-fragment conversion stage.
depthClampEnable — clamp vs discard beyond near/far
rasterizerDiscardEnable — kills all output
polygonMode — FILL / LINE / POINT
lineWidth — >1.0f needs wideLines feature
cullMode + frontFace — face culling
depthBiasEnable — shadow map depth offset
VkPipelineMultisampleStateCreateInfo
MSAA configuration. rasterizationSamples = VK_SAMPLE_COUNT_1_BIT disables multisampling. Enabling it requires a GPU feature.
VkPipelineColorBlendAttachmentState
Per-framebuffer blend settings.
blendEnable — gate for color mixing
srcColor/dstColorBlendFactor + colorBlendOp
srcAlpha/dstAlphaBlendFactor + alphaBlendOp
colorWriteMask — R/G/B/A channel gates
VkPipelineColorBlendStateCreateInfo
Global blend settings referencing the per-attachment struct.
logicOpEnable — bitwise blend (disables mixing)
attachmentCount + pAttachments
blendConstants[4]
VkPipelineLayout
Declares descriptor set layouts and push constant ranges accessible to shaders. Required even when empty; stored as a class member; destroyed in cleanup().

Logic Flow

The fixed-functions chapter is essentially a declaration form for every aspect of the pipeline that doesn't involve writing shader code. Vulkan requires all of this to be specified upfront — unlike OpenGL where you could call glBlendFunc or glPolygonMode at any time. The upside is that the driver sees the complete state at pipeline creation and can compile an optimally-tuned GPU program. The downside is verbosity: each configuration category needs its own create-info struct.

Dynamic state is the escape hatch. A small set of states can be declared as "dynamic," meaning their values are not baked into the pipeline — they are provided via command buffer commands at draw time. Viewport and scissor are the most common because they change whenever a window is resized or when rendering to different regions of the framebuffer. Making them dynamic means one pipeline can serve many window sizes. Crucially, even dynamic states still require their counts to be declared at pipeline creation; only the actual values (the VkViewport and VkRect2D structs) are deferred.

The rasterization state has several fields worth understanding precisely. rasterizerDiscardEnable = VK_TRUE is a nuclear option — it kills all rasterization output, effectively turning the pipeline into a vertex-only processor. depthClampEnable = VK_TRUE changes what happens to geometry that extends beyond the near or far depth planes: instead of being clipped away, those fragments are pushed to the plane boundary. This requires the depthClamp device feature and is primarily used in shadow rendering techniques. polygonMode controls whether triangles are drawn solid (FILL), as wireframe edges (LINE), or as points (POINT) — the non-FILL modes require the fillModeNonSolid feature. Similarly, lineWidth above 1.0f requires wideLines.

Color blending has two levels. The per-attachment VkPipelineColorBlendAttachmentState controls whether blending is active (blendEnable) and, if so, how the new fragment color combines with the existing framebuffer value via a formula of blend factors and operations. The tutorial disables blending for the triangle (overwrite mode). Alpha blending — the standard transparency formula — sets srcColorBlendFactor to SRC_ALPHA and dstColorBlendFactor to ONE_MINUS_SRC_ALPHA, yielding: result = newAlpha × newColor + (1 − newAlpha) × oldColor. The global VkPipelineColorBlendStateCreateInfo references one or more per-attachment structs and adds an alternative: logicOpEnable = VK_TRUE switches to bitwise operations (AND, OR, XOR) instead of mixing — but this silently disables blendEnable on every attachment.

VkPipelineLayout is required even for a pipeline that uses no descriptor sets and no push constants. It specifies the complete interface between the pipeline and shader-accessible resources, and Vulkan needs this information even if it is empty. The layout is stored as a class member because it is referenced both during pipeline creation and potentially during draw calls. It must be explicitly destroyed with vkDestroyPipelineLayout in cleanup(), before the device is destroyed.

Quiz — 10 Questions
Q1
conceptual
Why are viewport and scissor typically declared as dynamic state rather than baked into the pipeline?
AViewport and scissor values cannot be known at pipeline creation time because they depend on GPU driver internals
BDynamic viewport/scissor avoids the need to declare viewportCount and scissorCount in VkPipelineViewportStateCreateInfo
CThey change frequently (e.g., window resize) and static baking would force a full pipeline recreation for each change; dynamic state allows values to be set per draw call at no pipeline cost
DDynamic viewport/scissor is required by the spec when the swap chain was created with VK_SHARING_MODE_CONCURRENT
Q2
gotcha
When viewport and scissor are declared as dynamic state, what must still be set in VkPipelineViewportStateCreateInfo at pipeline creation time?
AviewportCount and scissorCount — the number of viewports and scissors is baked into the pipeline even when their values are dynamic
BNothing — VkPipelineViewportStateCreateInfo can be entirely omitted when both states are dynamic
CThe pViewports and pScissors pointers must point to default values that are overridden at draw time
DminDepth and maxDepth in the VkViewport struct — only width, height, x, and y become dynamic
Q3
terminology
What is the difference between a viewport and a scissor rectangle?
AViewport clips geometry before rasterization; scissor clips fragments after the fragment shader runs
BViewport transforms NDC coordinates to framebuffer pixel coordinates; scissor is a pixel-space mask that discards fragments outside the rectangle without any coordinate transformation
CViewport controls depth range; scissor controls the XY rendering area — they are otherwise equivalent
DViewport is set per-draw-call; scissor is set per-render-pass and cannot change within a render pass
Q4
application
What does setting rasterizerDiscardEnable = VK_TRUE do, and when would you ever want that?
AIt enables early-z rejection — fragments that fail depth testing are discarded before running the fragment shader
BIt discards back-facing fragments, acting as a more aggressive version of cullMode = BACK_BIT
CIt discards fragments that fall outside the scissor rectangle before the color blend stage
DIt prevents geometry from ever reaching the rasterizer — no fragments are produced, nothing is written to the framebuffer; useful when only vertex/geometry stage processing is needed (e.g., transform feedback)
Q5
gotcha
Which three rasterization settings each require an optional GPU feature to be explicitly enabled?
AdepthClampEnable = VK_TRUE (needs depthClamp), polygonMode != FILL (needs fillModeNonSolid), lineWidth > 1.0f (needs wideLines)
BrasterizerDiscardEnable, depthBiasEnable, and cullMode = VK_CULL_MODE_BOTH
CAll three polygonMode values (FILL, LINE, POINT) require their own GPU feature flags
DfrontFace = COUNTER_CLOCKWISE, depthClampEnable, and lineWidth = 1.0f
Q6
conceptual
Why is multisampling (MSAA) more efficient than simply rendering at a higher resolution and downscaling?
AMSAA skips depth testing at sub-pixel sample points, reducing GPU memory bandwidth
BMSAA compresses the multiple samples into a single byte per pixel using hardware-accelerated run-length encoding
CWhen only one polygon covers a pixel, the fragment shader runs once regardless of sample count — MSAA takes multiple depth/coverage samples at sub-pixel positions without the full per-sample shader cost of supersampling
DMSAA renders at native resolution and applies a post-process blur, avoiding any sub-pixel sampling overhead
Q7
application
What srcColorBlendFactor and dstColorBlendFactor values produce standard alpha blending, and what does the resulting formula compute?
Asrc = ONE, dst = ZERO — result = newColor (overwrite, same as blendEnable = VK_FALSE)
Bsrc = SRC_ALPHA, dst = ONE_MINUS_SRC_ALPHA — result = newAlpha × newColor + (1 − newAlpha) × oldColor
Csrc = ONE_MINUS_DST_ALPHA, dst = DST_ALPHA — result = (1 − oldAlpha) × newColor + oldAlpha × oldColor
Dsrc = SRC_COLOR, dst = DST_COLOR — result = newColor × newColor + oldColor × oldColor
Q8
gotcha
What happens to blendEnable on all framebuffer attachments when logicOpEnable = VK_TRUE is set in VkPipelineColorBlendStateCreateInfo?
AblendEnable on each attachment is evaluated first; logicOp is applied only to attachments where blendEnable = VK_FALSE
BBoth methods run in sequence — logic op executes on the result of color blending
CEnabling logicOp requires also setting blendEnable = VK_TRUE on each attachment as a prerequisite
DlogicOpEnable = VK_TRUE automatically disables color blending on all attachments — it is as if blendEnable were VK_FALSE everywhere; the two methods are mutually exclusive
Q9
terminology
What is VkPipelineLayout, and why must it be created even when the pipeline uses no descriptor sets and no push constants?
AIt describes the complete interface between the pipeline and shader-accessible resources; Vulkan requires this information at pipeline creation regardless of whether any resources are used — there is no valid null alternative to pass
BIt is a performance hint that tells the driver how much GPU memory to pre-allocate for uniform buffers
CIt is only required when using push constants; an empty pipeline layout can be replaced by passing nullptr in VkGraphicsPipelineCreateInfo
DIt holds the VkShaderModule references so they can be destroyed after vkCreateGraphicsPipeline
Q10
gotcha
primitiveRestartEnable = VK_TRUE lets a special index value break geometry sequences. On which topology modes does this have any effect, and what does it do?
AAll topologies — the special index inserts a degenerate primitive (zero-area triangle) to signal a break between draw calls
BOnly TRIANGLE_LIST — it causes every third index to restart the sequence from the beginning of the index buffer
COnly _STRIP topologies (LINE_STRIP, TRIANGLE_STRIP, etc.) — the special index value (0xFFFF for uint16 / 0xFFFFFFFF for uint32) ends the current strip and starts a new one, enabling multiple disjoint strips in a single draw call
DOnly POINT_LIST — it resets the point counter so the next point renders at the origin regardless of its buffer value
