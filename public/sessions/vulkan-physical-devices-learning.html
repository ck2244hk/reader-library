Physical device selection is a pure query phase — no Vulkan object is created. The real decision is whether a GPU exposes a queue family that supports graphics commands, tracked cleanly with std::optional to avoid sentinel-value traps.

pickPhysicalDevice() — enumerate, evaluate, select
VkPhysicalDevice physicalDevice = VK_NULL_HANDLE; // class member void pickPhysicalDevice() { uint32_t deviceCount = 0; vkEnumeratePhysicalDevices(instance, &deviceCount, nullptr); if (deviceCount == 0) throw std::runtime_error("failed to find GPUs with Vulkan support!"); std::vector<VkPhysicalDevice> devices(deviceCount); vkEnumeratePhysicalDevices(instance, &deviceCount, devices.data()); for (const auto& device : devices) { if (isDeviceSuitable(device)) { physicalDevice = device; break; } } if (physicalDevice == VK_NULL_HANDLE) throw std::runtime_error("failed to find a suitable GPU!"); }
QueueFamilyIndices struct and findQueueFamilies()
struct QueueFamilyIndices { std::optional<uint32_t> graphicsFamily; bool isComplete() { return graphicsFamily.has_value(); } }; QueueFamilyIndices findQueueFamilies(VkPhysicalDevice device) { QueueFamilyIndices indices; uint32_t queueFamilyCount = 0; vkGetPhysicalDeviceQueueFamilyProperties(device, &queueFamilyCount, nullptr); std::vector<VkQueueFamilyProperties> queueFamilies(queueFamilyCount); vkGetPhysicalDeviceQueueFamilyProperties(device, &queueFamilyCount, queueFamilies.data()); int i = 0; for (const auto& queueFamily : queueFamilies) { if (queueFamily.queueFlags & VK_QUEUE_GRAPHICS_BIT) indices.graphicsFamily = i; if (indices.isComplete()) break; i++; } return indices; }

Logic Flow

With a VkInstance in hand, the next task is selecting which GPU to use. This chapter is purely a query phase — no new Vulkan object is created. VkPhysicalDevice handles are enumerated from the instance using the familiar two-call pattern, and when the instance is destroyed those handles are implicitly cleaned up. There is nothing to add to cleanup().

The suitability check is where the chapter's design philosophy appears. The tutorial starts with isDeviceSuitable returning true — any GPU will do for now — but shows how to upgrade it with vkGetPhysicalDeviceProperties (device name, type, hardware limits) and vkGetPhysicalDeviceFeatures (optional capability flags). The scoring approach using std::multimap<int, VkPhysicalDevice> is presented as a production-worthy alternative: score each GPU, sort by score, pick the best. The key insight is that a hard requirement like geometry shader support should return 0 (eliminating the device entirely), while nice-to-haves like discrete GPU type add to the score without being blocking.

Queue families are the conceptual core of this chapter. A GPU doesn't expose one monolithic command queue — it exposes multiple families, each supporting a specific subset of operations. Graphics commands go to a graphics family. Compute shaders go to a compute family. Memory transfers can go to a dedicated transfer family. An application must identify the index of each family it needs before creating a logical device, because the logical device creation struct requires those indices.

The QueueFamilyIndices struct solves a subtle C++ problem. You need to distinguish "found queue family at index 0" from "haven't found one yet." A plain uint32_t initialised to -1 (which wraps to 4294967295 as an unsigned value) is technically valid but semantically fragile — what if index 4294967295 somehow existed? C++17's std::optional cleanly expresses the absence of a value: has_value() is false until explicitly assigned. This is not just stylistic; subsequent chapters add more required families (like a present queue for surface rendering), and the pattern scales cleanly: add another optional field to the struct, update isComplete(), and the rest of the code adapts automatically.

The isComplete() early-exit pattern in the search loop is an efficiency detail that matters more as the number of required families grows. Once all required indices are found there's no point scanning the remaining families. The break on isComplete() inside the loop means the search stops as soon as the struct is fully populated.

Step-by-Step — Selecting a Physical Device
  1. Add VkPhysicalDevice physicalDevice = VK_NULL_HANDLE as a private class member
    WHYThe handle must outlive pickPhysicalDevice() so later chapters (logical device, swap chain) can reference it. Initialising to VK_NULL_HANDLE makes the post-loop failure check unambiguous.
    WATCH OUTDo NOT add a vkDestroyXXX call in cleanup() — VkPhysicalDevice handles are owned by the instance and freed automatically when the instance is destroyed.
  2. Add pickPhysicalDevice() and call it from initVulkan() after setupDebugMessenger()
    WHYPhysical device selection depends on a valid VkInstance but doesn't need the debug messenger — placing it after setupDebugMessenger() keeps the init sequence ordered by dependency.
  3. Query device count with vkEnumeratePhysicalDevices and throw if zero
    WHYA system with no Vulkan-capable GPU is a hard stop. Failing fast with a clear error message is better than crashing later with an uninitialised handle.
  4. Fill std::vector<VkPhysicalDevice> with the second call to vkEnumeratePhysicalDevices
    WHYSame two-call pattern as extension and layer enumeration: first call fills count, second fills data. The vector is sized from the count so no buffer overflow is possible.
  5. Define the QueueFamilyIndices struct with std::optional<uint32_t> graphicsFamily and isComplete()
    WHYstd::optional distinguishes "not yet found" from "found at index 0" without a magic sentinel value. isComplete() becomes the single update point as more required families are added in later chapters.
  6. Implement findQueueFamilies() using vkGetPhysicalDeviceQueueFamilyProperties
    WHYIterates every queue family on the device and checks queueFlags against VK_QUEUE_GRAPHICS_BIT. Assigns the matching index to graphicsFamily and breaks early once isComplete().
    • a. Two-call pattern to get count then fill vector of VkQueueFamilyProperties
    • b. Loop with integer index i; check queueFamily.queueFlags & VK_QUEUE_GRAPHICS_BIT
    • c. Break as soon as indices.isComplete() — no need to scan remaining families
  7. Implement isDeviceSuitable() to call findQueueFamilies and return indices.isComplete()
    WHYTies device selection to queue family availability — a GPU without a graphics queue cannot be used for rendering, no matter how capable it is otherwise.
  8. Loop through devices in pickPhysicalDevice(), store first suitable device, throw if none found
    WHYThe post-loop VK_NULL_HANDLE check ensures a clean error if isDeviceSuitable() rejected every device — the handle is never used in an uninitialised state.
    WATCH OUTThe tutorial uses first-match selection for simplicity. If your system has both integrated and discrete GPUs and Vulkan picks the wrong one, upgrade to the scoring approach with std::multimap.
