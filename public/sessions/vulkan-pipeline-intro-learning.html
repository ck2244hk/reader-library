The graphics pipeline is a fixed sequence of stages that transforms vertices and textures into pixels — some stages run custom shader code, others apply predefined logic you can only configure, and in Vulkan the entire pipeline is immutable once created.

Logic Flow

The graphics pipeline is best understood as an assembly line. Raw 3D geometry enters one end and colored pixels exit the other. The Input Assembler reads vertex data from buffers and optionally uses index buffers to share vertices between triangles. The assembled vertices flow into the Vertex Shader, which runs in parallel across all vertices, transforming their 3D positions into 2D screen coordinates and packaging any per-vertex attributes (colors, texture coordinates, normals) for downstream stages.

Two optional programmable stages follow. Tessellation Shaders subdivide geometry on the GPU — a low-polygon mesh can be smoothed into a high-resolution surface at render time, useful for terrain and curved surfaces. The Geometry Shader processes complete primitives (triangles, lines, points) and can emit additional primitives or discard them entirely. The tutorial flags the geometry shader as "not often used in practice" because it performs poorly on most hardware — the flexibility doesn't justify the GPU cost on typical desktop GPUs (Intel integrated GPUs are the notable exception).

Rasterization is where vector geometry becomes pixel fragments. The stage projects the 3D primitive onto the 2D screen grid, identifies which pixels it covers, and emits one fragment per covered pixel. Fragments outside the screen or depth-culled behind closer geometry are discarded. Importantly, the vertex shader's output values — colors, UVs, anything it passed along — are linearly interpolated across the primitive's surface at this point, giving each fragment a weighted combination of its surrounding vertices' values.

The surviving fragments enter the Fragment Shader, which determines the final color and depth written to the framebuffer. It can sample textures, compute lighting, and output to multiple render targets. The Fragment Shader can be disabled entirely when color output isn't needed — shadow map generation, for instance, only cares about depth values. Finally, the Color Blending stage reconciles cases where multiple fragments map to the same pixel: it can overwrite, add them together, or alpha-blend them, enabling transparency effects.

The critical architectural distinction from older APIs is immutability. In OpenGL or Direct3D 11, pipeline state could be changed at any time — swap shaders, modify blend mode, change rasterizer settings — with the driver adapting dynamically. Vulkan makes the pipeline almost entirely immutable. Changing anything meaningful (shaders, framebuffer format, blend function) requires building an entirely new VkPipeline object. The up-front cost is real: applications must create and manage multiple pipeline objects for different rendering configurations. The pay-off is equally real: because all state is known at pipeline creation time, the driver can compile and optimize the entire pipeline into final GPU machine code without speculative compilation or runtime patching.
